# E0135: a range pattern that cannot match

A range pattern takes `i64`, `u8` or `char`, and matches at least one value: `5..=4` and `5..5` match none.

## Why

A range compares a value with its bounds, so it needs a type whose values are ordered: an integer, or a `char` by its code point. A `string`, `bool` or enum has no such order in a pattern. A range that matches no value is a mistake, usually bounds in the wrong order, and Rust rejects it too.

## Broken

```sisu
fn first_half(c: char) -> bool {
    match c {
        "a".."n" => true
        _ => false
    }
}

fn main() {
    print(first_half('c'))
}
```

## Fixed

```sisu
fn first_half(c: char) -> bool {
    match c {
        'a'..'n' => true
        _ => false
    }
}

fn main() {
    print(first_half('c'))
}
```
