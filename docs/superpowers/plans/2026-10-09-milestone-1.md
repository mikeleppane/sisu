# Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sisuc` compiles Sisu source with `i64`, `bool`, functions, `if`, `while` and recursion to a native executable; `fib.sisu` prints `832040` and `primes.sisu` prints `9592`.

**Architecture:** A hand-written pipeline in `crates/sisuc/src`: `lexer.rs` (tokens with inserted `Newline`s), `parser.rs` (recursive descent plus Pratt) into `ast.rs`, `check.rs` (validation only, no typed tree), and `codegen.rs` (inkwell, `var` as entry-block `alloca` promoted by `mem2reg`). `diagnostic.rs` holds spans and renders rustc-style errors through `annotate-snippets`. `sisu-runtime` gains `sisu_panic` and `sisu_print_bool`.

**Tech Stack:** Rust 2024 (toolchain pinned in `rust-toolchain.toml`), inkwell 0.10.0 with `llvm22-1`, LLVM 22 in `.llvm/22`, annotate-snippets 0.12.16, cargo-nextest.

**Spec:** `docs/superpowers/specs/2026-10-08-milestone-1-design.md`. Read it before each stage; this plan adds the decisions the spec leaves open and does not repeat the language rules.

- `cargo nextest run --workspace` and `prek run --all-files` pass before every commit. Lint rules live in `[workspace.lints]`: no `unwrap()` outside tests (use `expect("why")`), `#[expect(lint, reason = "...")]` instead of `#[allow]`, no `todo!`/`unimplemented!`, every item in a binary crate is `pub(crate)` at most.
- prek and CI run `cargo clippy --workspace --all-targets -- -D warnings`, so every commit must be clean in both the normal and the test build. Two rules keep it so:
  - Add an item only in the task whose code or tests first use it.
  - An item that tests reach but no non-test code reaches yet gets `#[cfg_attr(not(test), expect(dead_code, reason = "wired into the CLI in Task N"))]` on the outermost dead declaration (usually the `mod` line in `main.rs`, or one `pub(crate) fn`). Items reached only through it need nothing. The task that wires it in removes the attribute; `expect` fails the build if it is forgotten. A plain `#[expect(dead_code)]` fails in the test build, where the item is live.
  - When a task wires a module in but some of its items still have no non-test user (clippy names them), move the attribute onto those items; the task that first uses each one removes it. An attribute on a sibling module does not cover them.
- clippy pedantic is on. Expect `cast_sign_loss` on `i64 as u64` (use `i64::cast_unsigned`, e.g. for `const_int`) and `too_many_lines` on one big `lex` loop or `expr` match (split into helpers, such as one method per expression kind).

## Review Focus

1. **A file saved with CRLF line endings** compiles the same as with LF: the lexer skips `\r` as whitespace. Test `crlf_line_endings` in Task 3.
2. **A program that prints and then panics** still shows the lines printed before the panic. `println!` in the runtime flushes per line, and `process::exit` must not lose them. Test `overflow` checks stdout `1\n` in Task 15.
3. **An empty source file** gives "no `main` function" at `1:1`, rendered without a crash on an empty snippet. Test `empty_file_has_no_main` in Task 11.
4. **A function whose every path returns** (`if … { return -1 } else { return 1 }`) compiles to verified IR with no merge block left without a terminator. Tests `all_paths_return_is_fine` (Task 10) and `sign` in `semantics.sisu` (Task 14).
5. **A `var` declared inside a loop body** gets its `alloca` in the entry block, so `mem2reg` promotes it and the stack does not grow per iteration. Test `mem2reg_removes_every_alloca` in Task 16.

### Task 3: Newline insertion, brackets and layout errors

**Files:** Modify `crates/sisuc/src/lexer.rs`.

**Interfaces:** No new items. `lex` now emits `Newline` tokens: span of the `\n` byte, or an empty span at `source.len()` at end of file. The `Eof` token gets an empty span at the end of the last token that is not a `Newline` (`0..0` when there is none), so an error "found end of file" points just after the last code on its line, and `line_col` and annotate-snippets agree on it (annotate-snippets places an offset past a trailing `\n` on the previous line).

Rules (spec, "Statements end at newlines"): insert `Newline` at a `\n` or at end of file when the previous emitted token is `Ident`, `Int`, `True`, `False`, `Return`, `RParen` or `RBrace`, and the bracket stack is empty or its top is `{`. Decisions the spec leaves to the plan:
- Values: `fn expr(&mut self, e: &Expr) -> Option<IntValue<'ctx>>`; `None` means `unit` or `never`. `bool` is `i1`, `i64` is `i64`.
- Locals: a scope stack of `HashMap<String, Local>` with `enum Local { Value(IntValue<'ctx>) }`. Task 16 adds `Slot { ptr: PointerValue<'ctx>, ty: IntType<'ctx> }`.
- A block stops emitting statements as soon as the builder's current block has a terminator (`get_insert_block().and_then(|b| b.get_terminator()).is_some()`). That is how `never` ends a block.
- At the end of a function body, if the current block has no terminator, the declared return type picks the `ret`, never whether the body produced a value: `-> T` returns the body value; no `-> T` gives `ret void` and discards any body value.
- `if`/`else` with a value: create the merge block only if at least one branch falls through; the `phi` gets one incoming edge per branch that falls through, from the block where that branch ended. With no fall-through branch, leave the builder in a terminated block.
- `&&`, `||` and comparison chains use the same then/merge pattern with an `i1` phi. Each middle operand of a chain is evaluated once and reused.
- `print`: `sisu_print_int(i64)` for an `i64` argument, `sisu_print_bool(i1 zeroext)` for an `i1` one. Add the `zeroext` attribute to parameter 0 of the declaration and of each call site (`Attribute::get_named_enum_kind_id("zeroext")`), so the C `bool` ABI holds.
- Names: every user function is `sisu.<name>`, `main` included (`define void @sisu.main()`). Codegen adds `define i32 @main()` that calls `@sisu.main` and returns 0. So an explicit `return` in Sisu `main` is a plain `ret void`, and a Sisu call to `main()` is an ordinary `unit` call.
